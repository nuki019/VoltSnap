# VoltSnap 电路图拍照识别与仿真软件策划案（优化版）

## 0. 项目定位

VoltSnap 面向高校电路课程、实验报告和自学场景。用户拍摄纸质或屏幕上的大学基础电路图，软件自动识别元件、导线拓扑和参数，生成可编辑 SPICE 网表，并完成基础电路仿真与结果可视化。

本项目的关键不是单纯“识别图片中的元件”，而是把图片恢复成可仿真的电路结构。因此系统必须同时解决三件事：

1. 识别元件、文字参数和引脚位置。
2. 从导线像素中重建真实电气节点。
3. 生成可运行、可修正、可解释的 SPICE 网表。

---

## 1. 首版边界与目标

### 1.1 首版 MVP

建议首版聚焦“大学基础电路题图”，先把可控场景做扎实：

| 范围 | 首版支持 | 暂缓支持 |
|---|---|---|
| 输入来源 | 清晰拍照、截图、扫描图 | 严重弯曲纸张、遮挡、低清手写图 |
| 图纸类型 | 印刷体、电子版、规整手绘 | 非规整草稿、复杂教材排版混图 |
| 元件类型 | R、C、L、独立电压源、独立电流源、GND、导线、节点、简单开关 | 大规模 IC、PCB、复杂数字电路、继电器等 |
| 仿真类型 | 直流工作点 `.op`、瞬态 `.tran`、基础交流 `.ac` | 噪声分析、温度扫描、复杂模型库 |
| 交互方式 | 自动识别 + 用户校正 + 再仿真 | 完全无人干预的“一拍即准” |

首版产品应该明确允许用户校正识别结果。电路仿真对拓扑错误非常敏感，哪怕只有一根线断开，都可能导致仿真失败。把“人工确认和快速修改”设计成正式功能，比追求 100% 自动识别更容易落地。

### 1.2 首版验收指标

建议用可量化指标推动开发：

| 指标 | MVP 目标 |
|---|---|
| 清晰截图/扫描图元件检测召回率 | >= 95% |
| 普通手机拍照元件检测召回率 | >= 85% |
| 参数 OCR 准确率 | >= 85% |
| 拓扑节点完全正确率 | >= 75% |
| 用户校正后仿真成功率 | >= 90% |
| 单张图处理耗时 | 普通笔记本 <= 8 秒 |
| 用户从导入到看到结果 | <= 3 步主流程 |

## 2. 产品流程

```text
导入图片
  ↓
图片质量检测与透视矫正
  ↓
元件、文字、导线识别
  ↓
拓扑重建与网表生成
  ↓
用户检查和修正
  ↓
SPICE 仿真
  ↓
波形、节点电压、电流结果展示
  ↓
导出图片、网表、数据报告
```

核心界面建议采用三栏结构：

1. 左侧显示原始图片和识别框叠加层。
2. 中间显示重建后的电路结构、节点和可编辑参数。
3. 右侧或底部显示仿真设置、网表和波形结果。

## 3. 技术总体架构

```text
数据生成层
  SKiDL + schemdraw 合成 / KiCad 长期格式 / 随机电路生成 / 标注导出 / 图像退化

识别推理层
  图像预处理 / 元件检测 / OCR / 导线语义分割 / 引脚定位 / Edge VLM 辅助

拓扑重建层
  导线骨架化 / 连通域分析 / 线段拟合(LSD) / 引脚吸附 / 节点合并 / 规则校验

图网络构建层
  转化为 NetworkX 图结构 / 孤立点检测 / 短路检测 / 拓扑完整性校验

仿真执行层
  网表生成 / 单位解析 / 网表修复 / ngspice 仿真 / 结果解析

桌面应用层
  图片导入 / 识别预览 / 人工修正 / 仿真设置 / 波形展示 / 导出
```

建议采用”模块化替换”设计。比如元件检测一开始可以用 YOLO OBB，后续如果实例分割或关键点模型效果更好，可以替换模型而不改动仿真和界面。

**架构核心设计原则：** 电路本质上是一个图（Graph）结构——元件是边或节点，导线是超边（Hyperedge）。在拓扑重建层和仿真执行层之间，明确加入”图网络构建层”，使用 NetworkX 建立完整的电路拓扑图，再翻译为标准 ngspice 网表字符串。这样拓扑校验、孤立点检测、短路检测都在图层面完成，而非在原始像素或字符串层面硬编码。

## 4. 数据生成引擎

### 4.1 数据源策略

训练数据不要只依赖随机生成。建议使用三类数据混合：

| 数据来源 | 用途 | 优点 | 风险 |
|---|---|---|---|
| EDA 自动生成数据 | 大规模预训练 | 标注天然准确、数量大 | 与真实拍照有差异 |
| 教材/题库风格模板 | 提升大学场景适配 | 更接近目标用户 | 模板需要人工整理 |
| 真实拍照标注数据 | 最终效果校准 | 直接贴近使用场景 | 标注成本高 |

推荐策略：

1. 先用 5 万到 20 万张合成图训练基础模型。
2. 再收集 500 到 2000 张真实图片做精调和验证。
3. 上线后收集用户修正样本，进入主动学习闭环。

### 4.2 EDA 与生成工具选择

优先建议使用开放工具链作为核心：

| 工具 | 建议用途 | 优先级 |
|---|---|---|
| SKiDL | 用 Python 声明电路拓扑和网表，天然自带节点信息 | **阶段 1 核心** |
| schemdraw | 根据拓扑直接在 Python 里画图，坐标像素级精准可控 | **阶段 1 核心** |
| KiCad 原理图文件 | 作为长期主数据格式，开放、可解析、可版本化 | 阶段 2+ 逐步迁移 |
| ngspice | 仿真引擎，适合本地集成 | 全程 |
| LTspice / pyLTspice | 可作为兼容路线，不建议作为唯一核心依赖 | 可选 |

**阶段 1 强力推荐以 `schemdraw` + `SKiDL` 作为核心合成引擎。** 原因：

1. `SKiDL` 用 Python 声明电路拓扑，天然自带网表结构和节点信息，无需额外解析。
2. `schemdraw` 直接根据拓扑画图，其坐标是完全数字化、像素级精准可控的。可以极其轻松地在代码里控制某条线往左挪 10 像素、把电阻拉长 5 像素，并直接秒级导出边界框和引脚坐标。
3. KiCad 的 `.kicad_sch` 文件版本间格式变化大（v5 到 v8 经历了巨大重构），且其渲染依赖 KiCad 自身的源码或特定 Python 绑定，批量生成和动态随机微调的工程代码写起来非常繁琐。
4. KiCad 更适合作为阶段 2+ 的长期数据格式和导入/导出兼容能力，而非阶段 1 的核心生成引擎。

原因：项目如果深度依赖某个闭源 EDA 的私有格式，后期批量生成、自动标注和商业分发都可能受限制。schemdraw + SKiDL + ngspice 构成完全开放的底层管线。

### 4.4 电路模板库

模板不宜完全随机，否则会产生大量电学上没有意义的图。建议按课程知识点生成：

| 难度 | 模板类型 |
|---|---|
| 简单 | 串联电阻、并联电阻、分压电路、RC 充放电 |
| 中等 | RLC、桥式网络、一阶/二阶动态电路、受控源基础题 |
| 进阶 | 二极管限幅、简单运放反相/同相放大、滤波器 |

每个模板支持随机化：

1. 元件数。
2. 元件参数。
3. 排版方向。
4. 线段折线路径。
5. 符号风格，如 IEC、ANSI、教材简化符号。
6. 文本位置和写法，如 `4.7k`、`4k7`、`10uF`、`10μF`。

### 4.5 图像退化增强

合成图必须模拟真实输入，否则模型只会识别“完美矢量图”。

| 退化类型 | 模拟场景 |
|---|---|
| 透视变换 | 手机斜拍 |
| 旋转和裁剪 | 拍摄角度不正、边缘缺失 |
| 高斯模糊和运动模糊 | 对焦不准、手抖 |
| 光照不均和阴影 | 桌面、教室、实验室灯光 |
| 纸张纹理 | 打印纸、笔记本、扫描件 |
| 压缩噪声 | 微信、QQ、截图压缩 |
| 线条断裂 | 打印断墨、拍照低分辨率 |
| 墨水扩散 | 手写或低质量打印 |
| 屏幕摩尔纹 | 拍摄电脑或投影屏幕 |

注意：退化增强要有强度分级，不能一开始就把图片破坏得过重。建议采用课程式训练：

1. 第 1 阶段：干净图 + 轻微退化。
2. 第 2 阶段：中等拍照退化。
3. 第 3 阶段：加入真实照片和困难样本。

## 5. 图像识别方案

### 5.1 图像预处理

预处理目标是输出更稳定的识别输入，而不是把图像强行变成完美黑白图。

建议流程：

```text
原图
  ↓
质量评估：清晰度、亮度、对比度、是否过曝
  ↓
纸面/图框检测
  ↓
透视矫正
  ↓
去噪、对比度增强、灰度化
  ↓
二值图和灰度图双路输出
```

保留灰度图很重要。OCR 和部分模型可能需要灰度细节，不能只依赖二值图。

### 5.2 元件识别

首版建议使用“元件检测 + 引脚推断”的组合方案：

1. 使用 OBB 检测模型识别旋转元件，输出类别、中心、宽高和角度。
2. 对二端元件，根据类别模板和旋转角推断引脚位置。
3. 对多引脚元件，如运放、三极管，后续改用关键点检测或实例分割。

不要把模型方案绑定死在某个具体版本名称上。建议在工程文档中写为：

> 目标检测模型采用支持旋转框的 YOLO OBB 或同类检测模型，最终以验证集准确率、推理速度和部署难度为准。

这样后续可以根据实际效果选择 YOLO OBB、RT-DETR、实例分割或轻量关键点模型。

### 5.3 OCR 与参数绑定

OCR 需要识别两类文字：

1. 元件编号，如 `R1`、`C2`、`V1`。
2. 参数值，如 `10k`、`4.7uF`、`5V`、`1mA`。

绑定规则建议采用”空间距离 + 类型约束 + 方向关系 + 全局最优匹配”：

```text
OCR 文本
  ↓
单位和格式解析（电学语义先验）
  ↓
构建类型-单位强约束矩阵
  ↓
匈牙利算法全局最优匹配
  ↓
绑定到最高分元件
```

**关键优化：引入”电学语义先验”和全局最优匹配。**

文本与元件的绑定如果只靠空间距离和相对位置，在紧凑的教材电路图（如桥式整流桥、多级放大电路）中会高频出错。必须加入 **”类型-单位”强约束矩阵**：

- 如果 OCR 识别到了 `10uF`，候选绑定元件列表里电容（C）的权重赋予最高，电阻（R）和电压源（V）的权重直接降为 0。
- 利用位置相对关系：教材排版中，文本通常在电阻的**正上方/正下方**，或者垂直电阻的**左侧/右侧**。应将其作为几何先验加入打分系统（Cost Matrix）。
- 然后用**匈牙利算法（Hungarian Algorithm）**做全局最优匹配，而不是简单的最近邻搜索。这样可以避免多个文本框争夺同一个元件、或一个元件被多个文本误绑定的问题。

必须加入单位标准化：

| 输入写法 | 标准化结果 |
|---|---|
| `4k7` | `4.7k` |
| `10μF` | `10uF` |
| `1MΩ` | `1Meg` |
| `0.1u` | `0.1uF` |

### 5.4 导线识别

导线是拓扑重建的核心，不能只靠元件检测。

建议采用两条路线并行验证：

| 路线 | 方法 | 优点 | 缺点 |
|---|---|---|---|
| 传统图像路线 | 二值化、元件擦除、骨架化、连通域 | 开发快、可解释 | 对断线、噪点敏感 |
| 语义分割路线 | 训练 wire mask 模型 | 对噪声、断线和复杂背景更鲁棒 | 需要标注数据 |

**核心建议：语义分割路线应尽早提升到最高优先级。**

传统骨架化方案在真实手机拍照或教材截图中存在致命痛点：文字、元件引脚常常和导线粘连。当你擦除文字和元件后，导线会留下大量的**断裂空洞**和**毛刺**。传统骨架化（如 Zhang-Suen 算法）对断线极其敏感，会导致拓扑节点（Net）直接碎成一地渣，后续的"引脚吸附"会变成算法地狱。

**优化方案：**

1. 利用神经网络输出干净的 Wire Mask，让模型去抵抗光照、断墨和噪声。
2. 在得到 Mask 后，先进行**形态学闭运算（Closing）**连接微小断裂，再进行骨架化。
3. **补充步骤**：引入**线段检测器（如 LSD / Let-Tr）**。电路图的导线绝大多数是横平竖直的，用线段拟合比纯像素连通域更鲁棒。

MVP 阶段可以先用传统图像路线跑通闭环验证可行性，但阶段 2 必须切换到语义分割路线。

### 5.5 Edge VLM 辅助识别层（2026 技术红利）

2026 年端侧运行的轻量级多模态大模型（Edge VLM，如 Qwen2-VL-7B 或更小的量化版本）已经非常成熟，具备极强的结构化输出能力。建议将 VLM 作为**高级辅助/兜底验证层**集成到架构中。

**定位：** VLM 不是替代 YOLO + OCR 主流水线，而是作为互补的安全网。

**使用场景：**

1. 当传统 YOLO + OCR 链路遇到高难度、低置信度的区域时（如复杂受控源、模糊手写符号），将该局部区域切片丢给本地 VLM，用 Prompt 询问："这是一个什么元件？上面的数值是多少？"
2. 当拓扑重建出现歧义时（如两条导线是否相连），用 VLM 做视觉确认。
3. 作为训练数据标注的辅助工具，降低人工标注成本。

**集成方式：**

```text
主流水线（YOLO + OCR）
  ↓
置信度评估
  ↓
低置信度区域切片 → Edge VLM → 结果合并
  ↓
最终识别结果
```

**注意：** VLM 推理速度较慢（秒级），仅用于低置信度区域的兜底，不能用于全图实时推理。首版可暂不集成，但架构应预留接口。

## 6. 拓扑重建方案

### 6.1 基础流程

```text
二值图 / 导线 mask
  ↓
擦除元件主体，保留引脚附近区域
  ↓
骨架化，将导线压缩为单像素中心线
  ↓
检测端点、交点、拐点
  ↓
连通域标记，形成候选 Net
  ↓
引脚吸附到最近导线或端点
  ↓
节点合并与规则校验
  ↓
生成电气拓扑图
```

### 6.2 引脚吸附

由于检测框和导线像素都会有误差，引脚不能只判断“坐标是否刚好落在导线上”。应使用容错半径：

1. 在引脚预测点周围搜索最近的导线像素。
2. 搜索半径根据图像尺寸和线宽动态调整。
3. 若附近有多个候选 Net，按距离、方向一致性和元件类型打分。
4. 低置信度结果在界面中高亮，要求用户确认。

### 6.3 拓扑校验规则

生成网表前应进行静态检查：

| 检查项 | 处理方式 |
|---|---|
| 没有 GND | 自动推断候选 GND，并让用户确认 |
| 悬空引脚 | 高亮提示，允许用户连接或忽略 |
| 单节点短接异常 | 提示可能识别错误 |
| 电源缺少回路 | 提示无法仿真 |
| 参数缺失 | 使用默认值并要求用户确认 |
| 重名元件 | 自动重命名 |

拓扑重建不要追求“偷偷修好所有问题”。凡是可能改变电路含义的修复，都应该展示给用户确认。

## 7. 仿真与网表生成

### 7.1 仿真引擎

建议首版使用 ngspice：

1. 原型阶段可通过命令行调用 ngspice，稳定、易调试。
2. 产品阶段再考虑 PySpice 或动态库集成，减少磁盘读写和窗口依赖。
3. 所有仿真输入输出都保留日志，便于定位错误。

### 7.2 网表生成

从拓扑图生成 SPICE 网表时，需要统一处理：

1. 元件命名：`R`、`C`、`L`、`V`、`I` 前缀。
2. 节点命名：GND 必须映射为 `0`。
3. 单位解析：k、Meg、m、u、n、p。
4. 默认值：缺失参数先提示用户，不应直接静默仿真。
5. 模型库：二极管、三极管等需要默认模型或用户选择模型。

### 7.3 仿真结果展示

首版建议支持：

| 功能 | 说明 |
|---|---|
| 直流工作点 | 显示各节点电压和元件电流 |
| 瞬态分析 | 绘制指定节点电压随时间变化 |
| 交流分析 | 幅频和相频曲线 |
| 网表预览 | 用户可查看和复制 |
| 错误解释 | 将 ngspice 报错翻译成用户可理解的提示 |

## 8. 桌面客户端设计

### 8.1 技术选型

| 模块 | 推荐方案 |
|---|---|
| 桌面界面 | PyQt6 |
| 图像处理 | OpenCV |
| 模型推理 | ONNX Runtime |
| OCR | PaddleOCR 轻量模型或同类本地 OCR |
| 仿真 | ngspice |
| 波形绘制 | PyQtGraph 或 Matplotlib |
| 打包 | Nuitka 或 PyInstaller |

PyQtGraph 在交互式波形上通常比 Matplotlib 更轻快，Matplotlib 更适合导出静态图。可以二者结合：界面显示用 PyQtGraph，导出报告用 Matplotlib。

### 8.2 用户体验重点

必须做好的不是“界面好看”，而是减少用户修正成本：

1. 识别结果叠加显示在原图上。
2. 元件框、文字绑定、节点连接都可以点选修改。
3. 低置信度区域自动高亮。
4. 用户点击一根导线时，高亮同一个电气节点。
5. 用户修改参数后自动更新网表。
6. 仿真失败时定位到可能出错的元件或节点。

### 8.3 异步架构

识别和仿真都不能阻塞界面：

```text
Main Thread
  负责界面、交互、结果展示

Inference Worker
  负责预处理、模型推理、拓扑重建

Simulation Worker
  负责网表生成、ngspice 调用、结果解析

Data Worker
  负责加载模型、缓存样本、保存用户修正
```

## 9. 模型训练与迭代闭环

### 9.1 标注对象

训练数据应至少包含：

1. 元件旋转框。
2. 元件类别。
3. 引脚点。
4. 文本框和文本内容。
5. 文本与元件的绑定关系。
6. 导线 mask 或 polyline。
7. 电气 Net ID。

只有元件框是不够的。没有引脚点和 Net ID，模型即使检测准确，也无法稳定生成可仿真的网表。

### 9.2 主动学习

上线后建立数据闭环：

```text
用户导入图片
  ↓
模型识别
  ↓
用户修正
  ↓
保存修正前后差异
  ↓
筛选高价值样本
  ↓
加入训练集
  ↓
周期性更新模型
```

优先收集以下样本：

1. 模型低置信度样本。
2. 用户修改较多的样本。
3. 仿真失败但用户修正成功的样本。
4. 新符号风格、新教材来源、新拍照环境样本。

## 10. 开发路线图

### 阶段 0：可行性验证（2 周）

目标：证明“图片到可仿真网表”的最小闭环可行。

交付物：

1. 20 到 50 张简单电路样例。
2. 元件检测或手工标注输入。
3. 导线骨架化和连通域拓扑重建 demo。
4. 自动生成 ngspice 网表并完成 `.op` 仿真。

### 阶段 1：数据生成管线（3 到 4 周）

目标：建立可持续扩充的数据资产。

交付物：

1. 模板化电路生成器。
2. 图片、网表、坐标、引脚、Net ID 的统一 JSON 标注。
3. 图像退化增强管线。
4. 数据集划分和质量统计脚本。

### 阶段 2：识别模型 MVP（4 到 6 周）

目标：完成元件、文本和基础导线识别。

交付物：

1. 元件检测模型。
2. OCR 参数识别与绑定。
3. 基础导线 mask 或传统图像识别方案。
4. 第一版评估报告。

### 阶段 3：拓扑与仿真闭环（4 到 6 周）

目标：从识别结果稳定生成可仿真的网表。

交付物：

1. 引脚吸附和 Net 合并算法。
2. 网表生成器。
3. ngspice 调用与结果解析。
4. 仿真错误提示和修复建议。

### 阶段 4：桌面应用 MVP（4 周）

目标：让真实用户可以完成导入、识别、修正、仿真、导出。

交付物：

1. PyQt6 桌面界面。
2. 识别结果叠加预览。
3. 元件和节点编辑能力。
4. 波形展示和数据导出。
5. Windows 打包版本。

### 阶段 5：真实场景测试与迭代（持续）

目标：提升对真实拍照和不同教材风格的适配。

交付物：

1. 真实照片测试集。
2. 错误类型统计。
3. 数据闭环工具。
4. 模型和算法迭代计划。

## 11. 关键风险与应对

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| 合成数据与真实照片差距大 | 高 | 训练集表现好，实拍表现差 | 加入真实标注集、增强纸张/光照/模糊、主动学习 |
| 拓扑重建错误 | 高 | 元件识别对，但仿真失败 | 引脚关键点、导线分割、低置信度人工确认 |
| OCR 参数识别错误 | 中 | 10k 识别成 100k | 单位规则、上下文绑定、参数范围检查 |
| GND 自动判断错误 | 中 | 仿真节点错误 | 自动候选 + 用户确认 |
| ngspice 收敛失败 | 中 | 网表正确但不收敛 | 错误解释、默认仿真设置、用户调整入口 |
| 过早支持复杂元件 | 高 | 开发周期失控 | 首版限制元件库，分阶段扩展 |
| 完全自动化承诺过高 | 高 | 用户预期过高 | 产品定位为”自动识别 + 快速校正 + 仿真” |
| Python 打包体积与启动速度爆炸 | 中 | 包含 OpenCV、ONNX Runtime、PaddleOCR 后，PyInstaller 打包出来的 exe 超过 800MB，启动黑框长达数秒 | 1. 采用 Nuitka 深度编译；2. OCR 放弃 PaddleOCR 全家桶，改用更轻量的 `onnx-owl-ocr` 或原生 C++ OCR 库；3. 模型量化（INT8）减小体积；4. 如允许联网可考虑 C/S 架构 |

## 12. 推荐技术路线总结

| 模块 | 推荐路线 |
|---|---|
| 数据生成 | 阶段 1：SKiDL + schemdraw 核心合成；阶段 2+：KiCad 作为长期格式 |
| 图像增强 | OpenCV + Albumentations，课程式退化强度分级 |
| 元件识别 | 支持旋转框的检测模型（YOLO OBB 或同类），部署为 ONNX |
| 引脚定位 | 二端元件模板推断，多引脚元件逐步升级关键点模型 |
| OCR | 本地轻量 OCR + 电学语义先验 + 匈牙利算法全局匹配 |
| 导线识别 | MVP 传统骨架化验证，阶段 2 切换到语义分割 + 形态学闭运算 + LSD 线段拟合 |
| 拓扑重建 | 连通域 + 引脚吸附 + NetworkX 图结构校验 |
| 高级辅助 | Edge VLM 作为低置信度区域兜底（阶段 2+） |
| 仿真 | ngspice 优先，PySpice 作为封装选项 |
| 桌面端 | PyQt6 + 后台 Worker + PyQtGraph 交互波形 |
| 打包 | Nuitka 优先（体积小、启动快），OCR 选用轻量方案控制包体 |

## 13. 最重要的产品判断

VoltSnap 的核心竞争力不在于“用了多新的神经网络”，而在于形成一条闭环：

```text
可控生成数据
  ↓
稳定识别元件和文本
  ↓
可解释地重建拓扑
  ↓
生成可修改网表
  ↓
完成本地仿真
  ↓
把用户修正反哺训练数据
```

因此，开发优先级应为：

1. 先跑通简单电路的端到端闭环。
2. 再提升真实拍照鲁棒性。
3. 再扩大元件库和仿真类型。
4. 最后考虑云端、多用户、复杂编辑器等扩展功能。

只要首版能在“清晰大学基础电路图”上做到识别、修正和仿真顺畅，就已经具备很强的展示价值和继续迭代价值。
