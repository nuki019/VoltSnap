## 一、 数据生成引擎 (Data Pipeline)

这是你的技术壁垒，核心任务是生成“逼真的伪造电路图”以解决工业级目标检测的样本饥饿。

### 1. 矢量电路图自动生成

* **工具选型** ：利用 Python 库 `pyLTspice` 操纵 `.asc` 文件，或者直接用 `schemdraw` 库在后台随机组合电路。
* **生成逻辑** ：

1. 建立元件库池（电阻、电容、运放等）。
2. 基于图论随机生成合理的电路拓扑网格（确保有源电路、无源电路比例均衡）。
3. 自动导出两份文件：**干净的电路图 (PNG)** 和  **标准 SPICE 网表 (.net)** 。
4. 通过网表中的坐标，直接换算出 YOLO 格式的标签（类别、中心点、宽高、旋转角度 **$\theta$**）。

### 2. 图像“图层退化”算法 (Domain Adaptation)

用 `Albumentations` 库建立管道，强制将完美的矢量图变成“手机拍出来的效果”：

| **退化步骤** | **实现技术 / OpenCV 算子**                                   | **模拟现实场景**          |
| ------------------ | ------------------------------------------------------------------ | ------------------------------- |
| **空间变形** | `PerspectiveTransform`(透视变换)                                 | 模拟用户拍照时倾斜、对焦不正    |
| **光照污染** | `RandomShadow`+`GaussianNoise`                                 | 模拟寝室/实验室日光灯阴影与反光 |
| **介质融合** | 随机将背景与纸张纹理、屏幕像素网格做色彩混合 (`cv2.addWeighted`) | 模拟打印纸张、电子屏幕截图      |
| **退色磨损** | `Erode`/`Dilate`+ 随机对比度降低                               | 模拟打印机断墨、线条断裂        |

## 二、 图像预处理引擎 (Vision Preprocessing)

用户输入的图片第一站，目标是产出一张**正向、高对比度、黑白分明**的二值化图。

**Plaintext**

```
[输入图片] ──► 1. 边缘检测(Canny) ──► 2. 寻找最大四边形 ──► 3. 透视矫正(WarpPerspective) ──► 4. 自适应二值化 ──► [干净二值图]
```

1. **倾斜与透视矫正** ：

* 利用 `cv2.Canny()` 提取边缘，通过 `cv2.findContours()` 筛选出面积最大的四边形。
* 计算四个顶点，使用 `cv2.getPerspectiveTransform()` 和 `cv2.warpPerspective()` 将倾斜的电路图拉正。

1. **自适应去噪与二值化** ：

* 使用自适应阈值 `cv2.adaptiveThreshold(..., cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY, ...)`。
* 该算法能完美吃掉由于手机拍照产生的“局部高光”和“边缘阴影”，只留下纯黑的线条与纯白的背景。

## 三、 AI 推理核心引擎 (AI Inference Core)

本地显卡调度的核心，采用 **ONNX Runtime (GPU/DirectML)** 进行加速，摆脱 PyTorch 庞大的环境依赖。

### 1. 元件检测：YOLOv11-OBB (Oriented Bounding Boxes)

* **为什么用 OBB** ：传统矩形框无法处理旋转 45° 或 90° 的元件，OBB 可以输出 **$[x_c, y_c, w, h, \theta]$**。
* **引脚空间推算** ：
  已知元件中心坐标 **$(x_c, y_c)$**、未旋转时的引脚相对偏移 **$(\Delta x, \Delta y)$** 以及 YOLO 输出的旋转角 **$\theta$**，通过旋转矩阵实时算出各引脚在图像中的绝对坐标 **$(x_p, y_p)$**：

$$
$$x_p = x_c + \Delta x \cos\theta - \Delta y \sin\theta
$$

$$
$$y_p = y_c + \Delta x \sin\theta + \Delta y \cos\theta
$$

### 2. 参数识别：OCR 与语义绑定

* **工具** ：本地部署 `PaddleOCR` 或 `EasyOCR` 的轻量化量化模型。
* **绑定算法（启发式空间距离 + 正则）** ：

1. OCR 检出文本字符串（如 "4.7k"）及其包围框。
2. 计算该文本框中心与所有 YOLO 元件框中心的 **欧氏距离** 。
3. 结合正则匹配：若文本含 "Ω/k/M" 则强制绑定到最近的 **电阻** ；含 "V/mV" 绑定到 **电源** 。

## 四、 拓扑重建引擎 (Topology Reconstruction)

这是本方案的核心技术壁垒： **把像素级线条变成电路节点的图结构** 。

**Plaintext**

```
[二值化电路图]
       │
       ▼
[擦除 YOLO 元件框] ──► 擦除后只剩下导线
       │
       ▼
[骨架化 (Thinning)] ──► 线条全部缩减为 1 像素宽的单线
       │
       ▼
[连通域标记 (CCL)]  ──► 每个独立的连通线条像素簇 = 一个 Net ID (节点)
       │
       ▼
[引脚求交匹配]     ──► 检查哪个元件的引脚坐标(xp, yp)落在了哪个 Net ID 上
```

1. **元件区域擦除** ：根据 YOLO 识别出的 Bounding Box，在二值化图上将这些区域填白（抹去元件，切断导线），此时整张图只剩下孤立的导线段。
2. **骨架化 (Skeletonization)** ：调用 `cv2.ximgproc.thinning()`，将粗细不一的导线压扁成  **1 像素宽的单像素骨架** ，消除导线粗细对碰撞检测的干扰。
3. **连通域标记 (CCL)** ：调用 `cv2.connectedComponentsWithStats()`。此时，每一条相互连接的导线网络会被赋予一个唯一的整数 ID（例如：导线网 A 标记为 1，导线网 B 标记为 2）。 **这些 ID 在电学上就是天然的节点（Net）** 。
4. **拓扑关联** ：遍历所有元件的引脚绝对坐标 **$(x_p, y_p)$**，查看该坐标落在哪个 ID 的导线像素上。

* *示例* ：电阻 R1 的 Pin1 落在 ID=1 的导线上，Pin2 落在 ID=2 的导线上。则生成拓扑数据：`R1 -> [Net1, Net2]`。

## 五、 仿真与容错引擎 (Simulation & Sanitizer)

### 1. 网表净化器 (Netlist Sanitizer)

由于 AI 识别有概率出现 1% 的断线，直接送入 SPICE 会导致引擎崩溃。必须在后台进行静态电路语义检查：

* **悬空引脚修复** ：检查是否有 Net 仅连接了一个元件的单个引脚。若有，自动在后台给该节点并联一个 **$1\times10^{12}\,\Omega$** 的极高阻值电阻到地（GND），防止矩阵奇异报错。
* **主接地（GND）判定** ：SPICE 必须有 `0` 节点。算法自动寻找连接元件最多、且处于图像最下方的 Net，将其重命名为 `0`。

### 2. 本地仿真执行

* **调用方式** ：通过 `PySpice` 动态组装网表，直接内存传参给内嵌的 `ngspice.dll`/`ngspice.so`，避免频繁读写磁盘。
* **计算返回** ：执行 `.op`（直流工作点分析）或 `.tran`（瞬态时域分析），将各节点电压、电流数组直接转化为 Python 字典。

## 六、 桌面客户端与本地打包 (GUI & Deployment)

### 1. PyQt6 异步架构

为了防止 AI 推理和仿真时界面卡死（Not Responding），必须采用 **多线程架构** ：

* **Main Thread** ：负责 GUI 渲染、波形绘制（嵌入 `Matplotlib`）。
* **Inference Thread (`QThread`)** ：负责 OpenCV 预处理 **$\rightarrow$** ONNX 推理 **$\rightarrow$** 拓扑重建。
* **Simulation Thread (`QThread`)** ：负责 PySpice 计算。
* 线程间通过 `pyqtSignal` 传递图像数据与网表文本。

### 2. 纯本地免安装打包

* **打包工具** ：使用 `Nuitka`（比 PyInstaller 编译成更难反编译的 C++ 二进制，且运行速度更快）或 `PyInstaller`。
* **体积瘦身策略** ：
* 严禁 `import torch`！全线使用 `onnxruntime-gpu` 或 `onnxruntime`（CPU版）。
* 在 `.spec` 文件中明确排除不必要的 Tcl/Tk、Qt3D 等庞大子模块。
* 将预训练好的 `.onnx` 模型文件、OCR 字典、`ngspice` 动态链接库作为 `datas` 资源文件打包进 `exe` 同级目录下。
